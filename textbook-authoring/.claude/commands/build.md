# /build - 개념 전개 설계

개념을 "이해"에서 "계산 가능"까지 단계적으로 전개한다.
샘플 대화의 흐름: 개념 설명 → 계산 예시 → 원리 재확인

## 사용법
```
/build [주제] --context [도메인] --from [drafts/[주제]-why.md]
```

## 실행 지침

### 1단계: 직관적 설명 (계산 없이)
- 수식 없이 개념의 핵심 아이디어를 설명
- 비유 또는 시각적 이미지를 활용
- /why에서 발견한 동기와 직접 연결

### 2단계: 핵심 정의 도입
- 정의를 엄밀하게 제시 (수식 포함)
- 정의의 각 요소가 왜 그렇게 생겼는지 설명
- 단순한 암기가 아니라 필연성 강조

### 3단계: 계산 예시 (3단계 난이도)
각 예시는 반드시 다음 구조:
```
상황 설정 → 식 세우기 → 계산 과정 → 결과 해석
```

- 예시 A: 숫자가 깔끔한 기본 계산
- 예시 B: 실제 도메인 데이터 사용 (--context 반영)
- 예시 C: 개념의 핵심 성질을 드러내는 계산

### 4단계: 핵심 성질 정리
- 계산에 사용되는 주요 성질 목록화
- 각 성질에 대해 "왜 성립하는가" 한 줄 설명 포함

### 5단계: 출력
`drafts/[주제]-build.md`에 저장:

```markdown
# [주제]: 개념 전개

## 직관 (수식 없이)
[비유 + /why와 연결]

## 정의
[엄밀한 정의 + 각 요소의 필연성]

## 계산 예시
### 예시 A: [기본]
### 예시 B: [도메인 맥락]
### 예시 C: [핵심 성질]

## 핵심 성질
| 성질 | 수식 | 왜 성립하는가 |

## 다음 단계
→ /problems [주제] --level 기초
→ /problems [주제] --level 수학
→ /problems [주제] --level 전공
```

## 품질 기준
- 계산 예시의 답이 틀리면 안 됨 (검증 필수)
- "자세한 것은 생략" 금지 — 모든 계산 과정 명시
- 각 단계가 이전 단계에서 자연스럽게 이어져야 함
