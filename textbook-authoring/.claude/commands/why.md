# /why - 학습 동기 설계

주제를 배워야 하는 이유를 설계한다.
다른 교재가 "이렇게 계산해"로 시작할 때, 이 교재는 "왜 존재하는가"로 시작한다.

## 사용법
```
/why [주제] --audience [고등학생|대학생|대학원생|일반인] --domain [수학|생물|물리|컴퓨터과학|범용]
```

## 실행 지침

### 1단계: 역사적/필연적 동기 분석
- 이 개념이 왜 만들어졌는가? 어떤 문제를 풀기 위해 등장했는가?
- 이 개념 없이 불편했던 실제 사례는 무엇인가?
- 발명/발견한 사람이 직면한 문제는 무엇이었는가?

### 2단계: 현실 세계 연결
- 오늘날 이 개념이 실제로 쓰이는 곳 3가지 이상 제시
- 가능하면 지정된 도메인과 연결 (--domain 참고)
- 학습자가 실제로 접할 수 있는 맥락으로 구체화

### 3단계: 학습 목표 설정
- 이 개념을 배우면 무엇을 할 수 있게 되는가?
- "계산할 수 있다"로 끝나는 명확한 능력 기술문 작성
- 이후 단계(/build, /problems)와 연결되는 로드맵 제시

### 4단계: 출력
다음 형식으로 `drafts/[주제]-why.md`에 저장:

```markdown
# [주제]: 왜 배우는가

## 이 개념이 태어난 이유
[역사적 맥락 + 해결한 문제]

## 실제 세계에서 마주치는 곳
[도메인별 구체적 사례 3개 이상]

## 이걸 배우면 할 수 있는 것
[명확한 능력 기술문]

## 다음 단계
→ /build [주제] --context [발견한 가장 강력한 도메인]
```

## 품질 기준
- "중요합니다", "필수입니다" 같은 당위적 표현 금지
- 학습자가 스스로 "아, 이게 필요하겠다"를 느끼도록 설계
- 최소 하나의 역사적 사례 포함 필수
